# Security Incident Response Plan

Last reviewed: 2026-09-21

## 1. Identify

Record who reported the issue, affected school/account, devices, time range, and suspected records. Preserve relevant security activity and hosting logs.

## 2. Contain

Revoke affected rack iPads, rotate coach access codes, invalidate sessions through the account code version, restrict affected integrations, and isolate compromised operator credentials.

## 3. Investigate

Determine the access path, accounts and records affected, duration, whether data was viewed or changed, and whether the event crossed school boundaries. Do not include student names in general-purpose incident channels unless necessary.

## 4. Recover

Patch the cause, restore verified data when needed, reissue credentials, test authorization boundaries, and monitor for recurrence.

## 5. Notify

Notify affected schools without unreasonable delay according to contract, applicable law, and school policy. Provide known scope, containment steps, recommended school actions, and a follow-up schedule. Legal counsel determines any regulatory or individual notification requirement.

## 6. Review

Complete a written post-incident review, assign corrective actions, verify completion, and update this plan and automated tests.

## Contacts To Maintain Outside The Repository

- Security incident owner
- Hosting and storage provider support
- School privacy/security contact
- Legal/privacy counsel
- Cyber-insurance contact, when applicable
